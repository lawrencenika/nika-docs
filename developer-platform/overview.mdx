## Build the NIKA geospatial stack

NIKA's Developer Platform has two complementary tools. **OnlyMap JS** is the frontend layer for building interactive WebGL maps in the browser. **NIKA GeoEngine** is the backend worker platform for packaging, testing, running, and hosting geoprocessing code with reproducible environments.

<Columns cols={2}>
  <Card title="OnlyMap JS — frontend map applications" icon="map" href="/onlymap/overview">
    Build interactive maps with HTML custom elements and WebGL. Declare layers, widgets, popups, interactions, and stories without setting up deck.gl directly or maintaining a bespoke map UI framework.
  </Card>
  <Card title="NIKA GeoEngine — backend processing workers" icon="server" href="/nika-geoengine/overview">
    Package Python or R geoprocessing workloads in isolated containers, test them locally, version them, and make them available in the cloud and through QGIS or ArcGIS Pro.
  </Card>
</Columns>

## Choose where to start

<Steps>
  <Step title="Build an interactive map">
    Start with [OnlyMap JS](/onlymap/overview) when your goal is a browser-based map application, a visualisation, or an embeddable map experience.
  </Step>
  <Step title="Package a geoprocessing workflow">
    Start with [NIKA GeoEngine](/nika-geoengine/overview), then follow [Installation & Setup](/guides/custom-geoprocess-deployment/installation) and [Your First Worker](/guides/custom-geoprocess-deployment/step-by-step).
  </Step>
  <Step title="Connect processing to GIS users">
    After publishing a worker, use the [QGIS](/nika-geoengine/qgis) or [ArcGIS Pro](/nika-geoengine/arcgis) integration so GIS users can run it without managing the local runtime themselves.
  </Step>
</Steps>

## Frontend and backend, clearly separated

OnlyMap JS owns the map interface: it renders data, responds to user interaction, and presents a geospatial experience in the browser. GeoEngine owns processing: it gives each worker its declared dependencies, compute environment, version history, tests, and deployment path.

Use either independently. Use both when an application needs a rich map interface alongside repeatable, compute-intensive geoprocessing.
