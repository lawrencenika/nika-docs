## Overview

OnlyMap JS (`@nika-js/onlymap`) turns a handful of HTML custom elements into a full interactive WebGL map. You declare layers, widgets, popups, interactions, and even guided tours as markup; the library owns rendering, data loading, live updates, picking, and validation. There is no imperative deck.gl setup, no shader code, and no build step — a single HTML file is a complete map application.

It is also designed to be written **by AI agents**: HTML is a reliable generation target, the package ships an agent skill and an `llms.txt`, and `OmMap.validate()` returns structured errors with actionable fixes — a real authoring feedback loop.

```html
<om-map center="[-122.42, 37.77]" zoom="11" basemap="positron">
  <om-layer id="quakes" type="ScatterplotLayer"
            data="./quakes.json"
            label="Earthquakes" color="#e63946"
            get-position="[$lon, $lat]"
            get-radius="scale($mag, sqrt, [2, 20], domain=[0, 8])"
            pickable></om-layer>
  <om-widget type="legend" position="top-right"></om-widget>
</om-map>
```

## Install

```bash
npm install @nika-js/onlymap
```

```js
import "@nika-js/onlymap";
import "@nika-js/onlymap/onlymapjs.css";
```

Or with no build step at all, straight from a CDN:

```html
<script type="module" src="https://esm.sh/@nika-js/onlymap"></script>
```

Two optional setup commands complete the toolchain:

- **`npx @nika-js/onlymap init`** — wires VS Code IntelliSense for every `om-*` element and attribute, plus `!`-prefixed manifest snippets (`!starter`, `!map`, …).
- **`npx -y skills add NikaGeospatial/onlymapjs --skill onlymapjs`** — installs the OnlyMap authoring skill into coding agents (Claude Code, Cursor, Codex), so they write correct manifests on the first pass.

## Key Features

### Declarative Everything
- **34 layer types by name**: all of deck.gl's core, geo, aggregation, and mesh layers (Scatterplot, GeoJson, Arc, Path, Heatmap, Hexagon, Trips, Tile, Tile3D, Scenegraph, …) plus a built-in `PopupLayer` for WebGL labels at scale and a native `COGLayer` for GeoTIFF rasters.
- **Live manifest**: the markup *is* the state. Change an attribute — from a widget, a behavior, a script, or devtools — and the map reconciles automatically.
- **Built-in undo/redo**: layer toggles, filter changes, basemap switches, element edits, and drawn sketches are all undoable (`<om-widget type="undo-redo">`, or just Cmd/Ctrl-Z).

### A Full 3D Scene, Still Just Attributes <sup>new in 0.3</sup>
- **Terrain**: `terrain="terrarium"` raises real elevation with zero configuration (keyless AWS tiles); geographic layers drape onto the surface automatically. Bring your own DEM tile URL or register presets.
- **Scene lighting**: `lighting="daylight|studio|flat|custom"` plus fine-grained `lighting-*` overrides — or `lighting-sun-date` to compute the sun's position from a real date and the map's location. A native `lighting` widget exposes it all as presets and sliders.
- **Snapshots**: `map.snapshot()` captures the composited basemap + WebGL canvas to a PNG data URL or Blob — the seam for print/export pipelines.

### Data That Stays Fresh
- **Formats**: JSON/GeoJSON, CSV/TSV, Apache Arrow and GeoArrow (columnar fast path, zstd IPC), Shapefile with `.dbf` attributes, KML — heavy parsers lazy-load on first use.
- **GeoTIFF / Cloud-Optimized GeoTIFF** <sup>new in 0.3.1</sup>: `<om-layer type="COGLayer" src="./dem.tif">` streams raster tiles by HTTP Range request; min/max restretch and colormap swaps are GPU uniforms (no refetch), nodata renders transparent.
- **Live sources**: WebSocket streams with upsert-by-key and burst coalescing, and polled REST snapshots via `refresh="5s"`.
- **Private endpoints**: `OmMap.configureData({ headers, credentials, fetch })` keeps credentials out of markup by design.

### Application UI Without an App Framework
- **Widgets**: legend, layer switcher, basemap switcher, lighting controls, zoom controls, undo/redo, scale bar, attribution, GPU filter sliders, live Vega-Lite charts, a drawing toolbar — or custom widgets with a typed runtime context (`ctx.data`, `ctx.stats`, `ctx.viewport`, `ctx.emit`).
- **Managed, adaptive layout** <sup>new in 0.4</sup>: `position` places a widget in one of 8 logical, RTL-aware slots (`top-start` … `bottom-end`) — same-slot widgets stack with flush edges and a shared gap, adjacent compact controls auto-cluster into one group, and provider attribution and the license badge are in-flow slot members so neither covers a widget. On narrow maps (≤640px by default, `--om-widget-fold-breakpoint` to change) managed widgets fold into accessible drawers; a slot dims while an open popup covers it. `<om-map widgets-hidden>` hides all authored chrome without destroying it (required attribution and the badge never hide), and `position="manual"` opts a widget out of management entirely.
- **Symbology-aware legends** <sup>new in 0.3</sup>: the legend reads each layer's actual color styling — continuous `scale()` ramps render as gradient bars with domain labels, threshold scales as discrete class ranges, categorical expressions as swatch palettes, raster colormaps as their ramp. No legend configuration, ever.
- **Themeable from plain CSS**: every built-in widget reads `--om-widget-*` custom properties (`om-map { --om-widget-bg: #111827; --om-widget-fg: #f9fafb; }`) — dark-mode your map UI with one rule, no JS.
- **Overlays and behaviors**: rich HTML popups anchored to map coordinates or picked features, and declarative `on="click|hover|drag|load"` interactions — no event-handler code.
- **Map stories**: guided tours as `<om-story>` steps that fire the same actions behaviors use — including basemap, lighting, and terrain changes — with a player widget and deterministic scrubbing.

### Built for Verification
- **`OmMap.validate(html)`** returns structured errors, each with a concrete fix; a live on-page error panel is one attribute away (`validate`).
- **Headless test harness**: `mountForTest` runs full behavioral tests (picks, widgets, overlays, real projection math) in jsdom/happy-dom with no WebGL.
- **Layout, checked like types** <sup>new in 0.4</sup>: `npx @nika-js/onlymap check-layout <manifest.html>` audits a page's real rendered widget layout in headless Chromium across a viewport-width sweep — no widgets overlap, each is hit-testable and in its slot, same-slot edges are flush — emitting structured `{severity, element, message, fix}` diagnostics and exiting 0/1. The same audit is importable as `auditLayout(page)` for your own Playwright suite.
- **React adapter**: `@nika-js/onlymap/react` provides `<OmMap>`, `<OmLayer>`, `<OmWidget>`, `<OmOverlay>`, and a typed `useOmMap()` hook over the same core — React owns state, the library never fights the virtual DOM.
- **Custom layer classes**: `@nika-js/onlymap/deck` re-exports the bundled deck.gl class surface, so `OmMap.registerLayer` extensions share the renderer's own class hierarchy — desktop apps register domain layers (local-file rasters, catalog sources) as first-class manifest types.

### Framework & Programmatic Integration <sup>new in 0.4</sup>
- **`MapController`**: a framework-grade programmatic front-end — typed `LayerDescriptor`s drive the same reconcile core with no DOM manifest, plus camera methods, `emit`, `injectPick`, `snapshot`, and `onViewChange`/`onMapPoint`/`onTilesetLoad` callbacks.
- **External-store contract**: `getStore(token)` exposes per-token `{subscribe, getSnapshot}` stores (`viewport`, `selection`, `layers`, `data:<id>`) with cached immutable snapshots and `origin` tagging — directly consumable by React's `useSyncExternalStore`, MobX, Redux, or Zustand.
- **Consumer events**: beyond `om-view-changed` (camera settled), `om-map-point` surfaces every click/hover map coordinate (the hook for custom capture tools the draw widget doesn't cover) and `om-tileset-load` surfaces a `Tile3DLayer`'s live `Tileset3D` for tools like region export.

## Roadmap

Mapbox GL basemaps, depth-interleaved 3D compositing, globe projection, SSE transport, multi-field filters, `dblclick` behaviors, the `transform` data pipeline, the typed fluent builder, and stories/draw as React components are designed but not yet shipped. The README's "Not implemented yet" section is kept honest release by release.
